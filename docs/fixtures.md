# IQ files and fixtures

One file format serves fixtures, recordings and playback: raw samples plus a JSON sidecar.

```
<name>.cf32    interleaved float32 I,Q little-endian, nominal range [-1, 1]
<name>.json    sidecar (below)
```

`.cu8` (rtl_sdr raw, offset-binary) is accepted by `FilePlaybackDevice` for convenience when a
sidecar exists; the engine converts on the fly. Everything Leyline writes is `.cf32`.

## Sidecar

```json
{
  "format": "cf32",
  "sample_rate": 2400000,
  "center_hz": 146520000,
  "samples": 2400000,
  "created_at_ns": 0,
  "anchor": { "host_time_ns": 0, "drift_ppm": 0 },
  "description": "NFM 1 kHz tone at +100 kHz, 2.5 kHz deviation, -20 dBFS over a -60 dBFS floor",
  "generator": { "tool": "leyfix", "version": "0.1.0", "seed": 1, "signals": [ ... ], "noise_dbfs": -60 },
  "expect": [
    { "mode": "NFM", "offset_hz": 100000, "bandwidth_hz": 12500,
      "audio": { "tone_hz": 1000, "min_snr_db": 30 },
      "meter": { "power_dbfs_min": -30, "power_dbfs_max": -10, "squelch_open": true } }
  ],
  "metadata": { "mode": "NFM", "frequency_hz": "146620000" }
}
```

- `format`, `sample_rate`, `center_hz` are required; everything else is optional.
- `anchor.host_time_ns` is the wall clock of sample 0 (recordings); 0 for synthetic fixtures.
- `expect` is what the engine's fixture tests assert. Each entry describes one channel to create on
  a capture of this file and what its demodulated audio / meters must satisfy. `audio.tone_hz` is
  checked as the dominant spectral peak of the demodulated audio; `min_snr_db` is peak power over
  the rest of the audio band. `meter.power_dbfs_min` / `meter.power_dbfs_max` bound the channel's
  reported in-bandwidth power (either may be omitted; `noise_floor` sets both to pin the floor to
  ±1.5 dB); `meter.squelch_open` is the expected squelch state at the reference threshold of −40 dBFS.
- `metadata` is the free-form map that `Resource.metadata` exposes for recordings.

## Fixture catalog (`make fixtures` → `fixtures/`, generated by `go/cmd/leyfix`)

Defaults: 2.4 MSPS, 1 s, seed 1, noise floor −60 dBFS. All signals sit off-centre so the DC spur
and the channelizer's NCO are exercised.

| name | signal | expect |
|---|---|---|
| `nfm_tone` | 1 kHz tone FM-modulated, ±2.5 kHz deviation, carrier +100 kHz, −20 dBFS | NFM @ +100 k, bw 12.5 k → 1 kHz tone, SNR ≥ 30 dB |
| `am_tone` | 1 kHz tone, 80 % AM, carrier −250 kHz, −20 dBFS | AM @ −250 k, bw 10 k → 1 kHz tone, SNR ≥ 25 dB |
| `usb_tone` | 1 kHz tone as USB (carrier suppressed) at +50 kHz, −20 dBFS | USB @ +50 k, bw 2.8 k → 1 kHz tone, SNR ≥ 25 dB |
| `cw` | keyed carrier at −40 kHz (10 wpm "CQ"), −20 dBFS | CW @ −40 k, bw 500 → 700 Hz tone while keyed |
| `wfm_tone` | 1 kHz tone FM-modulated, ±75 kHz deviation, carrier +400 kHz, −20 dBFS | WFM @ +400 k, bw 200 k → 1 kHz tone, SNR ≥ 30 dB |
| `noise_floor` | complex white noise only, −60 dBFS | any channel: meter power within ±1.5 dB of the expected in-bandwidth floor; squelch closed at −40 dBFS |
| `two_nfm` | two NFM tones (1 kHz @ +100 k, 2 kHz @ −300 k) | two channels in one capture, each hears only its tone |

`leyfix check fixtures/` re-reads each fixture and verifies `expect` with a straightforward float64
reference chain in Go (mix, FIR, decimate, discriminate). It is test tooling, not the engine —
the engine's Swift fixture tests are the acceptance tests of record — but it proves the fixtures are
sane on any platform and catches generator regressions in CI.
